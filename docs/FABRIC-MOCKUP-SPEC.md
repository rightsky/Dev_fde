# 목업의 「데이터 패브릭 관리」 기능 명세 정리와 현재 구현 대조

2026-10-17. 출처는 목업 분석 `docs/mockup-analysis/09_planes.md` 1절(markup 2427~2845 · 3251~3330, logic.js 807~1294 · 2572~2621). 목업은 전부 정적 화면이며, 실제 계산이 있던 부분은 1.5절에 따로 적는다.

## 1. 화면 목적 (목업 원문)

"데이터 평면(자산 매트릭스)과 처리 평면(AI 모델 · 규칙엔진 · 외부연계)을 한 곳에서 관리합니다. 사람 · 권한은 시스템 관리에서 다룹니다."

즉 목업의 패브릭은 **원천 파일 목록이 아니라 관제 화면**이었다. 데이터가 어느 계층 · 어느 구역에 있고, 카탈로그와 대조되는지, 어떤 모델과 외부 연계가 각 단계에 붙어 있는지를 한 화면에서 보는 것이 목적이다.

## 2. 탭 구성과 기능

### 탭 1 · 자산 매트릭스 (4계층 × 2구역)

| 계층 | 개방구역 | 통제구역 | 셀 클릭 시 패널 |
|---|---|---|---|
| 카탈로그 평면 | 공개 투영본 (DCAT 부분집합 · K축 · 리니지 요약) ◀ | 정본 (DCAT · PROV-O · LPG · SKOS · SHACL), 등록 n건 · 작성 중 n건 | 등록 데이터셋 수, SKOS 통제어휘 66코드, SHACL Shape 7개, 개방 투영 필터(샘플 · 프로파일 통계 제외) |
| 레이크 | 공개 원천 (이미 개방된 것만) | 원천 파일 · 정제 Parquet, 배지 "대조 불일치 1", 원본 보존 + 푸터에 식별자 · 활동ID | 파일 목록(위치 URI · 체크섬 · 연결 카탈로그), 버튼 대조 실행 · 적재 승인 · 보존 정책, "직접 업로드 미지원 → 적재 요청" |
| 마트 | 메타 문장화 코퍼스 (벡터DB① 탐색용) ◀ | 본문 코퍼스 · 학습셋 (벡터DB② RAG용), 배지 "미등록 2" | 코퍼스 · 임베딩 인덱스 · 학습셋 목록, 미등록 행에 dcat:Dataset 등록 · prov:Activity 소급 기록 · STEP 3 이동 |
| 모델 레지스트리 | 해당 없음 | 임베딩 모델 · sLLM (가중치 · 바이어스 · 모델카드) | 모델 3건(체크포인트 URI · 체크섬 · 모델카드 · 생성 Activity), 검증 승인(서빙 승격) |

- 우측 기본 패널 "패브릭 이상 징후": 대조 불일치 1 · 미등록 2 · 모델 검증 대기 1 · 외부 연계 오류 1 · Plan 초안 1 (클릭 시 해당 셀 · 탭으로 이동).
- 원칙 문구: "카탈로그 평면은 나머지 세 계층을 기술하는 상위 평면. 마트 산출물과 모델도 dcat:Dataset · prov:Activity 로 등록되어 리니지가 마트 경계에서 끊기지 않게 한다. ◀ 는 통제 → 개방 단방향 push".

### 탭 2 · 런타임 구성 (AI 모델 · 외부연계)

- KPI: 적용 AI 모델 3(sLLM 1 · 임베딩 1 · 양자화 1), AI 적용 단계 6/8, 외부 연계 5 활성(전체 9 · 오류 2 · 중지 2), 구성 변경 이력 27건.
- 표 "워크플로 8단계 × AI 모델 · 외부연계": 단계별로 규칙엔진 / sLLM / 임베딩 중 무엇이 붙는지와 외부 연계(공공데이터포털 API · MCP · 레이크 · 시스템 DB · Neo4j · Fuseki/GraphDB · 벡터DB), 상태(정상 · 점검 필요).
- 모델 레지스트리 현황 4건, 외부 연계 현황 7건(공공데이터포털 · 레이크 S3 · MCP 서버 · LDAP 조직도 · 시스템 DB eTAS/KOPSS/VDS · 전자결재 · 문서저장소), 스트림 처리 규칙 요약.

### 탭 3 · 스트림 관리 (정렬 · 이벤트)

- KPI 5개(활성 스트림 · 가동 Plan · 오늘 이벤트 · 지각 데이터 · 기상 미확정 판정).
- 합성 스트림 유입 드롭존(.jsonl · .ndjson · .csv · .parquet), 스트림 탭 추가, 데모 데이터 지우기 · 복원.
- 스트림 목록(temporalResolution · event-time 컬럼 · 타임존 · 워터마크 · late 정책 · 처리량 · 상태 · 선언 편집 → STEP 3).
- Plan 레지스트리(정렬 · 이벤트 · 복합 CEP, 버전 이력, 파라미터 편집, 가동 승인 → 파생 데이터셋 초안).
- 파생 이벤트 데이터셋 현황, 프로버넌스 입도 정책(3단), 인식 모델 레지스트리, 알림 구독.

## 3. 목업에서 실제로 동작하던 것과 시뮬레이션

| 구분 | 내용 |
|---|---|
| 실제 계산 | 레이크 파일 목록은 STEP 1 업로드 목록에서 생성(URI `s3://lake-ctrl/upload/` + 파일명). 합성 스트림 등록 · 탭 추가 · KPI 의 합성 수 |
| 시뮬레이션 | 대조 결과(첫 파일은 항상 "체크섬 미기록"), 모든 KPI · Plan · 이벤트 · 모델 수치, 등록 · 승인 · 저장 버튼 전부(토스트만) |
| 미구현 | 매트릭스 "등록 n건"은 상수 0, 합성 스트림을 넣어도 스트림 목록 표에는 행이 추가되지 않음 |

## 4. 목업 분석이 제안한 실제 제품 기능

1. 레이크 객체 인벤토리와 카탈로그 대조(체크섬 · 푸터 식별자) 배치, 불일치 큐, 적재 승인 워크플로
2. 마트 산출물(코퍼스 · 임베딩 인덱스 · 학습셋)의 dcat:Dataset 등록 추적과 소급 등록
3. 모델 레지스트리(체크포인트 URI · 체크섬 · 모델카드 · 생성 Activity · 서빙 상태 · 승격 승인)
4. 스트림 선언 미러, Plan CRUD 와 불변 버전, 가동 승인 시 파생 데이터셋 초안 자동 생성
5. 단계별 런타임 구성(모델 · 커넥터 매핑) 조회와 변경 이력

엔티티 초안: `lake_object` · `reconciliation_run` · `mart_asset` · `model` · `model_version` · `runtime_step_config` · `stream` · `plan` · `plan_version` · `derived_event_dataset` · `alert_subscription`.

## 5. 현재 구현과의 대조

| 목업 기능 | 현재 (v0.15) | 비고 |
|---|---|---|
| 자산 매트릭스 4계층 × 2구역 | 없음 | 지금 화면은 원천 자산(파일 · 스트림) 목록 하나 |
| 레이크 · 원천 파일 목록 | **있음** (업로드 보관소 + 프로파일, sha256 체크섬) | 레이크 연동 · 대조 배치 · 적재 승인은 없음 |
| 카탈로그 평면 (정본 · 투영본) | **있음**, 단 위치가 다름 (ARD 관리 › 발행본 · STEP 7) | 통제 → 개방 단방향 투영은 메타데이터 공개 수준 · MCP 노출 규칙으로 대체 |
| 마트 (코퍼스 · 임베딩 · 학습셋) | 없음 | 외부 sLLM/벡터DB 를 쓰지 않는 구조로 바뀜 |
| 모델 레지스트리 | 없음 | 모델은 Claude API 하나, 설정값 `FDE_AI_MODEL` |
| 런타임 구성 (단계 × 모델 × 연계) | 부분 | 단계별 모델 사용은 고정(STEP 3 초안 · STEP 7 시뮬레이션). 외부 연계 현황 화면 없음 |
| 스트림 관리 | **부분** (스트림 등록 · 스키마 · 시간 규격 · STEP 3 선언) | Plan 레지스트리 · 이벤트 판정 · 파생 데이터셋 · KPI 없음 |
| 이상 징후 패널 | 없음 | 검수 큐 신호와 STEP 8 진단이 일부 역할 |
| 외부 연계 (포털 · 레이크 · 시스템 DB · LDAP · 전자결재 · 문서저장소) | 없음 | README "만들지 않은 부분" |

요약하면 지금의 "데이터 패브릭 관리"는 목업의 **레이크(통제구역) 셀의 파일 목록 + 스트림 관리 탭의 등록 기능**만 남은 상태다. 목업이 그린 관제 기능(매트릭스 · 대조 · 마트 · 모델 · 런타임 구성 · Plan)은 외부 인프라(레이크 · 벡터DB · sLLM · Neo4j)를 전제로 한 것이라, 메타데이터 중심 · Claude API 구조로 바뀐 현재 제품과는 전제가 다르다.

## 6. 메타데이터 중심 서비스 기준으로 남길 것과 뺄 것 (제안)

| 남길 것 (현 방향과 맞음) | 이유 |
|---|---|
| 원천 자산 대장 (파일 · 스트림) + 프로파일 | 모든 프로세스의 후보, 기관 등급표 매칭 대상 |
| 카탈로그 평면 정본 · 투영 개념 | 메타데이터 공개 수준 · MCP 노출 규칙으로 이미 구현 |
| 스트림 선언(스키마 · 시간 규격) | DCAT DataService 발행에 필요 |
| 외부 연계 1종: **기관 DB 스키마 읽기 커넥터** (테이블 · 컬럼만) | 실제 데이터 없이 메타데이터를 가져오는 패브릭다운 기능, N²SF 부담 적음 |
| 외부 연계 현황 (읽기 전용 상태판) | 어떤 연결이 켜져 있는지 보안담당이 확인 (Claude API · MCP · 향후 커넥터) |

| 뺄 것 (전제가 바뀜) | 이유 |
|---|---|
| 마트 · 벡터DB · 코퍼스 등록 | 자체 sLLM/RAG 를 운영하지 않음 |
| 모델 레지스트리 · 양자화 변형 승격 | 모델이 외부 API 하나 |
| 레이크 대조 배치 · 적재 승인 | 데이터 본체를 다루지 않음. 데이터레이크 연계 단계에서 재검토 |
| Plan 레지스트리 · 이벤트 판정 · CEP | 스트림 처리 엔진이 아님 |
| 단계 × 모델 매트릭스 | 모델 선택지가 하나라 의미 없음 |

위 "남길 것"대로 가면 메뉴 이름 "데이터 패브릭 관리"는 유지하고, 부제를 "원천 자산 · 외부 연계"로 달아 STEP 1 의 업로드 입구를 이쪽으로 모으는 것이 자연스럽다.

## 7. v0.17 반영 결과

6절 "남길 것"대로 구현했다.

| 항목 | 구현 |
|---|---|
| STEP 1 업로드 입구 통합 | STEP 1 의 드롭존 · 스트림 등록 카드를 없애고 「데이터 패브릭 관리로 →」 안내로 바꿨다. 등록은 패브릭 화면에서만 한다 |
| 기관 DB 스키마 읽기 커넥터 | `db_connector` 테이블(0009), `services/connectors.py`, `/api/connectors` (등록 admin · 시험 · 동기화 worker · 삭제 admin). PostgreSQL · MySQL. 읽기 전용 세션, 스키마만 반영, 표마다 `asset(source=dbschema, connector_id)` |
| 외부 연계 현황판 | `/api/integrations` 읽기 전용. Claude API · MCP · DB 커넥터의 켜짐 · 범위 · 최근 사용 |
| 유형 필터 | 원천 자산 · STEP 1 모두 파일 · DB 스키마 · 스트림 3분류 |

뺀 것(마트 · 모델 레지스트리 · 레이크 대조 · Plan · 단계×모델 매트릭스)은 그대로 보류한다. 데이터레이크 연계가 실제 과제로 들어오면 "레이크 객체 인벤토리 + 카탈로그 대조"부터 재검토한다.
