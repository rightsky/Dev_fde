# N²SF C/S/O 를 테이블·컬럼 단위로 분류할 수 있는가

2026-10-17. 질문: 기관 메타데이터가 입력으로 들어오는 상황에서, 지금처럼 데이터셋 하나에 등급 하나를 매기는 대신 테이블과 컬럼 단위로 C/S/O 를 나눌 수 있는가.

## 1. 결론

**가능하고, 오히려 N²SF 의 원칙에 더 잘 맞는다.** 다만 "컬럼 등급이 데이터셋 등급을 대체"하는 것이 아니라 **"컬럼 등급에서 테이블·데이터셋 등급이 도출"** 되는 구조여야 한다.

근거는 세 가지다.

1. **N²SF 가이드라인 1.0(국정원, 2025.9)은 분류 대상을 "업무정보"와 "정보시스템"으로 두고, 여러 등급이 섞이면 가장 높은 등급을 따르게 한다.** 컬럼 단위를 금지하지도, 요구하지도 않는다. 즉 기관이 업무정보를 어느 입도로 식별할지는 기관 몫이고, 컬럼은 업무정보의 가장 작은 식별 단위다. "섞이면 최고 등급" 규칙은 그대로 컬럼 → 테이블 → 데이터셋 집계 규칙이 된다.
2. **등급 기준 자체가 정보 항목 단위다.** C 는 정보공개법 제9조제1항제1~4호(비밀·안보·국방·외교·수사·국민 안전), S 는 제5~8호(의사결정 과정 정보, 개인정보, 법인 영업비밀, 특정인 이익 정보)에 대응한다. 이 호들은 "이 레코드의 이 항목"에 걸리는 것이지 파일 전체에 걸리는 것이 아니다. 주민등록번호 컬럼 하나 때문에 통계 테이블 전체가 S 가 되는 것이 바로 데이터셋 단위 분류의 비용이다.
3. **AI Ready Data 의 목적이 "쓸 수 있는 부분을 열어 주는 것"이다.** 컬럼 등급이 있으면 C·S 컬럼을 뺀 **파생 배포본**을 O 로 발행할 수 있고, MCP 로 나가는 데이터 사전에서 C 컬럼을 이름조차 숨길 수 있으며, 에이전트 키의 등급(O/S)에 따라 컬럼을 다르게 보여 줄 수 있다. 데이터셋 단위에서는 이 셋이 모두 불가능하다.

## 2. 설계안

### 2.1 등급 모델 (3층)

| 층 | 등급 주체 | 결정 방식 | 저장 위치 |
|---|---|---|---|
| 컬럼 | 담당자 (자동 제안 + 확인) | 컬럼 이름·값 패턴·사전 정의·정보공개법 호 매핑으로 **제안**, 담당자가 확정 | 데이터 사전 (STEP 3 ③ 탭) `grade`, `grade_basis`(제9조 몇 호), `grade_by/at` |
| 테이블 | 자동 | `max(컬럼 등급)`. 담당자가 **상향**만 가능 (테이블 전체가 비밀 문서인 경우), 하향 불가 | 프로파일 테이블 메타 |
| 데이터셋 | 자동 + STEP 4 확인 | `max(테이블 등급)`. STEP 4 의 N2SF 축은 이 값을 **기본값**으로 받고 상향만 허용 | 지금의 `classification.N2SF` |

핵심 규칙은 하나다. **하위 단위가 상위 단위 등급을 올릴 수는 있어도 내릴 수는 없다** (high-water mark). 이 규칙이 N²SF 의 "섞이면 최고 등급" 과 같다.

### 2.2 자동 제안 기준 (컬럼)

| 제안 등급 | 신호 | 정보공개법 근거 |
|---|---|---|
| C 후보 | 컬럼명·사전 정의에 비밀·보안·작전·수사·첩보·시설 좌표(국가중요시설) 등, 기관이 등록한 C 어휘 사전 일치 | 제9조제1항 제1~4호 |
| S 후보 | 개인정보 식별자(주민·여권·운전면허·계좌·카드·전화·이메일·주소·생년월일·이름), 민감정보(건강·장애·종교·정치), 내부 의사결정(결재·검토의견), 법인 영업비밀 표시, 고유값 비율이 높은 자유 텍스트 | 제5~8호 |
| O | 위 신호 없음, 코드값·집계값·공개 좌표계 | 비해당 |
| 판단 보류 | 자유 텍스트 컬럼(서술형)은 값 안에 개인정보가 섞일 수 있어 담당자 확인 필수 | - |

지금 프로파일러의 `_PII_NAME` 정규식이 S 후보 탐지의 출발점이고, 여기에 기관별 C 어휘 사전(관리자 화면에서 등록)을 더하면 된다. 자동 제안은 어디까지나 제안이고, 확정은 담당자가 한다는 점을 화면에 명시해야 한다 (N²SF 는 기관 자체 분류를 요구한다).

### 2.3 등급이 바꾸는 동작

| 동작 | O 컬럼 | S 컬럼 | C 컬럼 |
|---|---|---|---|
| 프로파일 예시값 저장 | 저장 | 저장 안 함 (지금 PII 처리와 동일) | 저장 안 함 |
| 데이터 사전·카드 (내부 화면) | 전부 | 전부 | 전부 (등급 배지 표시) |
| 외부 산출물 (CSVW·Croissant·데이터 사전 CSV) | 포함 | 포함, 예시값 없음 | **컬럼 자체 제외**, 제외 사실만 "C 등급 컬럼 n개 비공개" 로 표기 |
| MCP `get_schema` | O 키·S 키 모두 | S 키만 | 어떤 키에도 비노출 (존재도 알리지 않음) |
| AI 초안 제안 전송 문맥 | 이름·통계 | 이름만 (값 통계 제외) | 이름도 제외 |
| 파생 배포본 발행 | - | S 컬럼 제외본을 O 로 발행 가능 | C 컬럼 제외본을 S 또는 O 로 발행 가능 |
| 데이터 결합(K 축) | 결합키 허용 | 결합키 허용하되 검수 큐 고위험 신호 | 결합키 금지 |

### 2.4 표준 표현

- **CSVW**: 컬럼 노드에 `fde:n2sfGrade <def/n2sf/S>` 와 `fde:gradeBasis "정보공개법 제9조제1항제6호"`. 테이블 스키마에 `fde:n2sfGrade`(집계값).
- **DCAT 3**: 데이터셋 `dcterms:accessRights` 는 지금처럼 집계 등급, 파생 배포본은 별도 `dcat:Distribution` 으로 두고 `dcterms:accessRights` 를 따로 가진다. 원본과의 관계는 `prov:wasDerivedFrom` + `fde:excludedColumns`.
- **ODRL**: C 컬럼 포함 배포본에는 `odrl:prohibition` 에 `odrl:action odrl:distribute` 를 자동으로 넣는다.
- **Croissant**: `rai:personalSensitiveInformation` 에 S 컬럼 목록을 자동 기재. C 컬럼은 Croissant 자체를 만들지 않는 쪽(외부 배포 금지)이 안전하다.
- **SHACL**: "C 컬럼이 있는 테이블의 데이터셋 등급은 C 여야 한다", "O 데이터셋에 S 이상 컬럼이 있어서는 안 된다" 두 shape 로 집계 규칙을 검증한다. 검증 실패는 STEP 6 에서 바로 보인다.

### 2.5 STEP 8 진단과의 연결

- 원칙 P-04(보안등급)·M-?? N2SF 항목은 지금 "등급 지정 여부"만 본다. 컬럼 등급이 들어오면 "컬럼 등급 확정률 n/N", "집계 규칙 위반 0건", "C 컬럼 외부 산출물 제외 확인" 세 가지를 자동 증빙으로 추가할 수 있다.
- 검수 큐 위험 신호에 "S 이상 컬럼 포함 발행", "파생 배포본과 원본 등급 불일치" 를 추가한다.

## 3. 한계와 주의

1. **값 기반 판정은 하지 않는다.** 컬럼 안의 값을 읽어 개인정보를 찾는 것은 그 자체가 민감 데이터 처리다. 컬럼명·사전 정의·통계(고유값 비율, 길이 분포)까지만 쓰고, 값은 담당자 화면에서만 보인다. 기관이 별도 개인정보 검출 솔루션을 쓰면 그 결과를 "제안" 입력으로 받는 연계 지점만 둔다.
2. **등급은 맥락을 탄다.** 같은 "주소" 컬럼이라도 공공시설 주소는 O, 민원인 주소는 S 다. 자동 제안이 테이블 성격(엔티티 종류: 사람 / 시설 / 사건 / 집계)을 함께 보도록 데이터 사전에 "행이 나타내는 대상" 한 칸을 추가하는 것이 정확도를 가장 크게 올린다.
3. **조합(결합) 위험은 컬럼 단위로 잡히지 않는다.** 각각 O 인 컬럼들이 결합되면 재식별이 가능하다(모자이크 효과). 이 부분은 지금의 K 축(연계키)과 검수 큐 "데이터 결합" 신호가 담당하고, 컬럼 등급으로 대체하지 않는다.
4. **상위 등급 결정은 여전히 기관 CISO·보안담당 몫이다.** 스튜디오는 제안과 집계·검증을 하고, "확정" 버튼과 기록을 남기는 데까지가 역할이다.

## 4. 재검토: 메타데이터 중심 서비스에서 컬럼 단위 C/S/O 가 필요한가 (가이드라인 v1.1 대조)

입력이 실제 데이터가 아니라 기관의 스키마(테이블·컬럼) 메타데이터인 현 단계를 전제로, 「공공데이터의 인공지능 친화적 관리 가이드라인 v1.1」이 등급에 대해 실제로 요구하는 것과 대조한 결과다.

| 가이드라인이 말하는 것 | 위치 | 단위 | 스튜디오 현재 | 판단 |
|---|---|---|---|---|
| 공유 데이터는 등록 전에 O/S/C 3등급으로 분류, "N2SF 기준에 따라 변경 가능" | 1.3.2 | **데이터셋** | STEP 4 N2SF 축 | 충족 |
| 카탈로그 필수 항목에 "데이터 등급 C/S/O 내지 1/2/3", "비식별 처리 여부", "컬럼 수 및 설명" | 표 (카탈로그 항목) | 데이터셋 (컬럼은 이름·타입·설명만) | 등급 facet, 데이터 사전 | 충족. 컬럼 등급은 요구 없음 |
| 데이터 등급 · 접근 자격 · 활용 조건 · 활용 환경을 **구분**해 관리 | 3.6.1 참고표 | 데이터셋 | 등급(N2SF 축) / 자격(에이전트 키·역할) / 조건(ODRL 표 39) / 환경(UI·MCP) | 충족, 네 축이 분리돼 있음 |
| 등급 판단 항목: 개인정보 유형 · 재식별 위험도 · 보안·법적 제한 · 처리 강도 · 산출물 성격 · 적합성 태그 | 3.6.1 예시표 | 데이터셋 | 검수 큐 위험 신호 일부(개인정보 의심·결합) | **부분**. 등급을 "왜" 그렇게 정했는지 구조화된 근거가 없음 |
| 제한공유(S)를 S1(조건부 공유)·S2(제한 공유)로 세분화 권장 | 3.6.1 | 데이터셋 | S 하나 | **미흡**, 코드 2개 추가로 해결 |
| 공유 불가 5유형(표 41): 고유식별정보, 국가보안, 제3자 제공 금지법, 재식별 위험 잔존 등 | 1.3.2 · 표 41 | 데이터셋 | 없음 | **미흡**, 체크리스트 + 발행 차단 |
| 결합으로 민감도가 오르면 공유 수준 재검토 | 3.6.1 | 조합 | 검수 큐 "데이터 결합" 신호 | 부분. "결합 후 등급 ≥ max(원본)" 자동 제안 없음 |
| 개인정보·민감정보 **항목** 발견 시 비식별 처리 · 기록, 접근등급 확정 시 "AI 에이전트 접근 허용 여부 명시" | 생애주기 표 (처리·가공, 등록) | **컬럼(항목)** 은 비식별 기록용, 등급은 데이터셋 | PII 컬럼 자동 탐지 → 예시값 제거, 전송 제외 표시 | 충족에 가까움. 요구되는 컬럼 단위 정보는 "민감 항목 여부와 비식별 처리 기록"이지 컬럼별 C/S/O 가 아님 |

**결론: 지금 단계에서 컬럼 단위 C/S/O 등급은 과하다.** 가이드라인의 등급 단위는 일관되게 데이터셋이고, 컬럼에 요구되는 것은 "개인정보·민감정보 항목 표시와 비식별 처리 기록" 뿐이다. 실제 데이터가 없는 메타데이터 중심 서비스에서는 값 기반 위험(재식별·추론)이 발생하지 않으므로, 컬럼 등급으로 얻는 효용(파생 배포본·컬럼 필터)도 당장은 작다.

대신 가이드라인이 요구하는데 비어 있는 것을 채우는 쪽이 맞다 (모두 데이터셋 단위, 합쳐서 1~2일):

1. **등급 판단 근거 체크리스트** (STEP 4): 개인정보 유형 5단계 · 재식별 위험 3단계 · 보안·법적 제한 4단계를 고르면 등급 **제안**과 근거가 함께 저장되고 정본에 `fde:gradeBasis` 로 남는다. 검수 큐와 STEP 8 증빙이 이 근거를 인용한다.
2. **S1 / S2 세분화**: N2SF 축에 `N2SF-S1`, `N2SF-S2` 코드 추가. MCP 키 등급에 S1 만 허용하는 선택지.
3. **표 41 공유 불가 5유형 점검**: 체크리스트에서 하나라도 해당하면 발행 차단(409) + 사유 표시. 고유식별정보는 컬럼 자동 탐지(주민·여권 패턴)로 미리 경고.
4. **결합 후 등급 재검토 제안**: STEP 2 조합 확정 시 "조합 등급 ≥ 구성 데이터셋 최고 등급" 을 기본값으로 제안하고, 낮추려면 사유 입력.
5. **컬럼 민감 항목 표시** (데이터 사전): 컬럼마다 "개인정보 유형"(비개인/가명/개인/민감·고유식별) 한 칸과 비식별 처리 방법·일시 기록. 이것이 가이드라인이 요구하는 컬럼 단위 정보의 전부다. 앞 절의 3층 컬럼 등급 모델은 이 칸을 토대로 **실제 데이터를 다루는 단계(데이터레이크 연계 이후)** 에 올리면 된다.

메타데이터 자체의 공개 수준은 별개 문제다. C 등급 시스템의 테이블·컬럼 이름은 그 자체가 S 이상일 수 있으므로, "데이터 등급"과 별도로 "메타데이터 공개 수준"(카탈로그 목록 공개 / 상세 공개 / 내부 한정)을 데이터셋에 두는 것을 권한다. 공공데이터법의 "목록은 공개, 데이터는 비공개" 원칙과도 맞고, 지금의 `ai_excluded`·C 비노출 규칙을 일반화한 것이다.

## 5. 구현 규모 (참고)

| 단계 | 내용 | 규모 |
|---|---|---|
| 1 | 데이터 사전에 컬럼 등급 칸 + 자동 제안 + 테이블·데이터셋 집계 + STEP 4 기본값 연동 | 중 (백엔드 2일, 화면 1일) |
| 2 | 외부 산출물·MCP·AI 전송에서 C 컬럼 제외, S 컬럼 키 등급 필터 | 중 (1~2일, 테스트 포함) |
| 3 | SHACL 집계 규칙, STEP 8 증빙, 검수 큐 신호 | 소 (1일) |
| 4 | 파생 배포본 발행 (컬럼 제외본) | 중 (2일, 정본 그래프 구조 변경) |

1~3 단계가 한 판(v0.12) 분량이다.
