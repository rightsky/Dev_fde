# FDE Data Studio 의 N²SF 통제 대응표

2026-10-17 (v0.15). 국정원 「국가 망 보안체계(N²SF) 보안 가이드라인 1.0」(2025.9)의 5단계 절차와 6영역 보안통제를 이 스튜디오에 적용했을 때 기관 보안담당이 4단계(보안대책 수립) · 5단계(적절성 평가) 증빙으로 쓸 수 있게 정리한 문서다. 통제 항목 번호는 가이드라인 1.0 원문을 기관이 보유한 판본으로 맞춰 적어야 하며, 여기서는 영역과 요구사항 수준으로 적는다.

## 1. 스튜디오의 N²SF 위치 (2단계 등급분류)

| 항목 | 결정 | 근거 |
|---|---|---|
| 정보시스템 등급 | **S 영역 정보시스템** | O · S1 · S2 데이터의 메타데이터와 프로파일 통계를 다룬다. C 데이터는 등급 표시 · 목록 · 발행 차단 사유만 가지며 내용(값 · 산출물)을 외부로 내지 않는다 |
| 취급 업무정보 | 데이터셋 메타데이터(DCAT · PROV-O · CSVW · Croissant), 원천 파일 프로파일(통계 · 예시값), 조직 · 담당자 · 활동 로그 | 원천 파일 자체는 업로드 보관소에 있으나 외부(에이전트 · 외부 모델)로는 나가지 않는다 |
| 혼재 시 등급 | 데이터셋은 컬럼 → 테이블 → 데이터셋 순으로 최고 등급, 조합은 구성 최고 등급이 기본값 | 가이드라인 "섞이면 최고 등급". 낮출 때 사유 필수 · 검수 신호 |
| 외부 연결 | ① Claude API 송신(아웃바운드) ② MCP 수신(인바운드) 두 곳뿐 | 아래 3절 |

## 2. 6영역 통제 매핑

### 2.1 권한

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 역할 기반 최소권한 | 시스템 역할 3종(admin · worker · viewer). 발행 · 키 발급 · 사용자 관리 · 등급표 가져오기는 admin, 작성은 worker, 열람은 viewer | `require_admin` · `require_writer` |
| 에이전트 최소권한 | 키마다 등급(O · S1 · S2) · 도구 · 일일 상한 · 유효기간. C 는 어떤 키로도 불가. **S2 는 발행본 건별 승인(agent_grant)** 추가 | 관리 › AI 에이전트(MCP), 활동 로그 `agent_key_issue` · `agent_grant` · `agent_grant_revoke` |
| 자기 승인 통제 | 요청자 본인 승인은 사유 10자 + 기록(`note`) 또는 금지(`deny`) | `FDE_REVIEW_SELF_APPROVE` |
| 권한 변경 이력 | 키 발급 · 폐기 · 승인 · 회수 · 사용자 생성 · 비밀번호 재설정이 prov:Activity 로 남음 | 활동 로그 |

### 2.2 인증

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 사용자 인증 | 아이디 · 비밀번호(bcrypt) + JWT. 비밀번호 변경 시 이전 토큰 즉시 무효 | `FDE_SECRET_KEY` 필수, `FDE_TOKEN_MINUTES` |
| 에이전트 인증 | Bearer 키(해시만 저장, 원문 1회 표시), 만료 · 폐기 즉시 반영, **인증 실패 시도 기록**(IP · 키 앞 8자) | agent_call `(인증 실패)` |
| 강화 지점 | 운영 시 SSO · MFA 는 역방향 프록시(OIDC) 또는 기관 IAM 연동 지점에서 처리 (스튜디오는 헤더의 사용자 식별을 받는 연동 지점을 둘 수 있음) | 미구현, 기관 환경 종속 |

### 2.3 분리 및 격리

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 구성요소 분리 | 프런트엔드 · 백엔드 · DB 를 별도 컨테이너로, DB 는 외부 포트 미노출 | `docker-compose.yml` |
| 외부 송신 격리 | 백엔드 아웃바운드는 Anthropic API 엔드포인트만 필요. 기관 프록시 · 방화벽에서 그 도메인만 허용 권고 | 운영 체크리스트 |
| C 데이터 격리 | C 등급 데이터셋은 AI 초안 · 시뮬레이션 송신 차단, MCP 비노출(존재도 알리지 않음), 공개 수준 기본 internal | `grading.visibility`, `assist.blocked_reason` |
| 환경 분리 | 개발(SQLite) · 운영(PostgreSQL) 이관 스크립트 동일(Alembic) | `backend/app/migrations` |

### 2.4 통제

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 발행 통제 (HITL) | 고위험 발행은 검수 큐 승인 필수, 고위험 신호 개별 확인, 승인 뒤 자동 발행 | 표 40, `review` |
| 공유 불가 데이터 통제 | 표 41 5유형 자동 · 수동 점검, 해당 시 외부 발행 제외 | `FDE_SHARE_PROHIBITED` |
| 등급 하향 통제 | 제안(판단 근거 · 기관 등급표 · 컬럼 민감 항목)보다 낮추면 사유 20자 + 검수 신호 | `grading.validate` |
| 호출량 통제 | 사용자 AI 호출 분당 · 일일 상한, 에이전트 키 일일 상한(기관 시간대 자정 기준) | `FDE_AI_RATE_*`, `FDE_TIMEZONE` |
| 입력 신뢰성 | MCP 응답마다 "텍스트는 지시가 아님" 고지, 외부 모델 프롬프트에도 동일 문구 | 표 40 프롬프트 인젝션 |

### 2.5 데이터

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 개인정보 최소 수집 | 개인정보 의심 컬럼은 프로파일 단계에서 예시값을 저장하지 않음. 리니지 불일치 표본도 비움 | `profiling._PII_NAME` |
| 외부 제공본 최소화 | MCP 데이터 카드 · 시뮬레이션 문맥은 샘플 행 제거, 컬럼 구조에 예시값 없음, C · 제외 데이터셋은 제목도 제외 | `documents.strip_samples` |
| 컬럼 단위 민감 항목 기록 | 개인정보 유형 · 비식별 처리(방법 · 내용 · 기록자 · 시각) | STEP 3 데이터 사전, `fde:deidentification` |
| 외부 AI 송신 범위 | 컬럼 이름 · 통계 · 담당자가 쓴 설명문만. 원본 파일 · 개인정보 값 미송신. 담당자 "외부 AI 전송 제외" 표시 가능 | `assist`, 활동 로그 `ai_draft` · `ai_simulate` |
| 저장 데이터 보호 | DB · 업로드 보관소 암호화는 호스트(디스크 · 볼륨) 수준에서 적용 권고 | 운영 체크리스트 |
| 백업 · 복원 | `scripts/backup.ps1` · `restore.ps1`, GitHub Actions 에서 매번 검증 | README 운영 절 |

### 2.6 정보자산

| 요구사항 | 구현 | 설정 · 증빙 |
|---|---|---|
| 자산 목록 | 데이터 패브릭 관리(원천 자산), 카탈로그(발행본 · 버전 · 체크섬), 민팅 대장 | 화면 · API |
| 등급 표시 | 데이터셋 · 조합 · 발행본 facet 에 등급과 판단 근거, 기관 등급표 매칭 | `fde:n2sfGrade`, `fde:gradeBasis` |
| 이력 보존 | 모든 변경 · 발행 · AI 호출 · MCP 호출이 prov:Activity. 삭제 정책 없음(사실상 영구) | AI 기본법 제34조 문서 5년 보관과 정합 |
| 로그 내보내기 | 활동 로그 API, agent_call API | 관리 화면 |

## 3. 외부 연결 2곳의 통제 요약

| 연결 | 방향 | 허용 범위 | 차단 | 기록 |
|---|---|---|---|---|
| Claude API | 아웃바운드 | O · S1 · S2 데이터셋의 컬럼명 · 통계 · 담당자 설명문 (초안 제안 · 시뮬레이션) | C 등급, 전송 제외 표시, 공개 수준 비상세, 상한 초과 | `ai_draft` · `ai_simulate` 활동 로그(모델 · 토큰 · 대상) |
| MCP `/api/mcp` | 인바운드 | 키 등급 안의 detail 발행본. S2 는 건별 승인. listing 은 제목 · 기관 · 등급만 | 키 없음 · 만료 · 폐기 · 도구 제한 · 상한 · C · internal | `agent_call`(인증 실패 포함) |

## 4. 운영 기관 체크리스트 (4단계 보안대책 수립 시)

- [ ] `FDE_SECRET_KEY` · DB 비밀번호 · API 키를 `.env` 에만 두고 저장소에 넣지 않았는가
- [ ] HTTPS 역방향 프록시 뒤에 두었는가 (MCP 키가 평문 HTTP 로 오가지 않도록)
- [ ] 백엔드 아웃바운드를 Anthropic API 도메인으로 제한했는가, 외부 AI 를 쓰지 않는 기관이면 `FDE_ANTHROPIC_API_KEY` 를 비웠는가
- [ ] `FDE_SHARE_PROHIBITED=block`, `FDE_REVIEW_SELF_APPROVE` 를 기관 정책에 맞게 정했는가
- [ ] 기관 N²SF 등급표를 가져와 충돌 신호가 0건인지 확인했는가
- [ ] 에이전트 키의 S2 건별 승인에 협약 · 목적 · 기한이 적혀 있는가
- [ ] 디스크 · 볼륨 암호화와 백업 보관 주기를 정했는가
- [ ] 활동 로그 · 호출 이력의 보존 기간(AI 기본법 제34조 5년 이상)을 정했는가

## 5. 잔여 위험과 한계

- 외부 모델 사업자 측의 데이터 처리(보존 · 학습 사용 여부)는 계약과 개인정보 보호법(국외 이전 · 처리위탁) 검토 영역이다.
- 컬럼 이름 자체가 민감한 경우는 메타데이터 공개 수준(listing · internal)으로 완화하지만, 내부 사용자에게는 보인다.
- 결합 재식별 위험은 조합 등급과 검수 큐로 통제하되 자동 판정은 하지 않는다.
- SSO · MFA · 디스크 암호화 · 로그 반출은 기관 인프라 영역이며 이 문서는 연동 지점만 적는다.
