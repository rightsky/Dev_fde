# N²SF 반영 기획안 (FDE Data Studio v0.12 ~ v0.13)

2026-10-17. 「공공데이터의 인공지능 친화적 관리 가이드라인 v1.1」 1.3.2 · 3.6.1 · 생애주기 표와 국정원 「국가 망 보안체계(N²SF) 보안 가이드라인 1.0」(2025.9)을 기준으로, 메타데이터 중심 서비스인 현 단계에 맞춰 N²SF 를 시스템에 넣는 방법을 정리한 것이다. 컬럼 단위 C/S/O 등급은 실제 데이터를 다루는 단계로 미루고(별도 문서 `N2SF-COLUMN-GRADING.md` 4절), 여기서는 데이터셋 단위에서 가이드라인이 요구하는 항목을 빠짐없이 채우는 데 집중한다.

## 1. 목표와 원칙

| 목표 | 뜻 |
|---|---|
| 등급에 **근거**가 남는다 | 담당자가 O/S/C 를 고르는 데서 끝나지 않고, 왜 그 등급인지(개인정보 유형 · 재식별 위험 · 보안·법적 제한)가 구조화되어 정본·검수·진단에 인용된다 |
| 등급이 **동작**을 결정한다 | 등급 · 접근 자격 · 활용 조건 · 활용 환경 네 축이 분리된 채로, 발행 가능 여부 · MCP 노출 · AI 전송 · 결합 허용이 등급과 근거에서 자동으로 따라온다 |
| 기관 분류를 **입력으로 받는다** | 기관이 N²SF 1단계(준비)에서 만든 업무정보 · 정보시스템 등급표를 가져와 기본값으로 쓰고, 스튜디오는 보정과 확정만 한다 |
| 메타데이터 자체의 공개 수준을 따로 둔다 | 데이터는 C 라도 "이런 데이터셋이 있다"는 목록은 공개할 수 있고, 반대로 테이블·컬럼 이름 자체가 민감한 경우도 있다 |
| 스튜디오 자신도 N²SF 대상 시스템이다 | 어느 영역(S)에 두고 어떤 외부 연결(Claude API · MCP)을 어떤 조건으로 허용하는지 통제 대응표로 문서화한다 |

원칙 세 가지: ① 값을 읽어 판정하지 않는다(컬럼명 · 사전 정의 · 통계 · 기관 분류표만 쓴다). ② 자동은 제안까지, 확정은 사람이 한다. ③ 낮추는 결정에는 사유가 필요하고 기록된다.

## 2. 등급 모델

### 2.1 데이터셋 등급 (기존 N2SF 축 확장)

| 코드 | 이름 | 가이드라인 대응 | 공유 범위 |
|---|---|---|---|
| `N2SF-O` | 공개 | 1등급(O) 공개공유 | 모든 기관 · 공공데이터포털 · 공개 에이전트 |
| `N2SF-S1` | 조건부 공유 | 3.6.1 S1 (비식별·집계 자료, 이용약정 전제) | 승인된 기관, 이용약정 체결 에이전트 키 |
| `N2SF-S2` | 제한 공유 | 3.6.1 S2 (개별 기록·민감 정보, 사전 승인·접근통제) | 기관 간 협약, 건별 승인 키 |
| `N2SF-C` | 비공개 | 3등급(C) 내부전용 | 기관 내부. 외부 반출 금지, 에이전트 비노출 |

기존 `N2SF-S` 는 `S2` 로 이관한다(보수적 기본값). 이관 스크립트가 기존 값을 바꾸고 활동 로그에 남긴다.

### 2.2 등급 판단 근거 (신규, 3.6.1 예시표)

STEP 4 N2SF 축 아래에 세 가지 선택 항목을 둔다. 고르면 등급이 **제안**되고, 담당자가 그대로 받거나 바꾼다.

| 항목 | 선택지 | 제안 규칙 |
|---|---|---|
| 개인정보 유형 | 비개인정보 / 익명정보 / 가명정보 / 개인정보 / 민감정보·고유식별정보 | 비개인·익명 → O 가능, 가명 → S1 이상, 개인 → S2 이상, 민감·고유식별 → C (표 41 유형 1) |
| 재식별 위험도 | 낮음(단독·결합 모두 곤란) / 중간(결합 시 가능) / 높음(단독 식별 가능) | 중간 → S1 이상, 높음 → S2 이상 + 결합 제한 태그 |
| 보안·법적 제한 | 일반공개 / 영업비밀·제3자 권리 / 법령상 비공개 / 국가안전 관련 | 영업비밀 → S1 이상, 법령상 비공개 · 국가안전 → C |

제안 등급 = 세 항목이 요구하는 최저 등급 중 가장 높은 것. 담당자가 제안보다 **낮게** 고르면 사유(20자 이상)를 받고 검수 큐 신호 `GRADE_BELOW_BASIS` 를 만든다. 세 항목 모두 비어 있으면 STEP 8 보안 항목이 "부분 충족"이 된다.

### 2.3 표 41 공유 불가 5유형 점검 (신규)

근거 항목과 컬럼 탐지로 자동 판정하고, 담당자가 확인란을 켠다.

| 유형 | 자동 신호 | 효과 |
|---|---|---|
| 고유식별정보 포함 | 컬럼명 패턴(주민·여권·운전면허·외국인등록) 또는 개인정보 유형 = 민감·고유식별 | 발행 차단(409 `SHARE_PROHIBITED`), AI 전송 제외 자동 |
| 국가보안사항 | 보안·법적 제한 = 국가안전 관련 | 발행 차단, C 강제 |
| 제3자 제공 금지 법률 | 관련 법령 칸에 의료법·신용정보법 등 등록된 법령 | 발행 차단, S2 이상 |
| 재식별 위험 잔존 | 재식별 위험 = 높음 + 비식별 처리 없음 | 발행 차단 |
| 기타 기관 지정 | 담당자 수동 체크 | 발행 차단 |

차단은 "발행 불가 사유"로 STEP 7 발행 카드와 검수 큐에 그대로 보인다. 내부 카탈로그(기관 한정)에는 등록할 수 있다.

### 2.4 메타데이터 공개 수준 (신규)

데이터 등급과 별개로 데이터셋마다 하나를 고른다. 기본값은 등급에서 도출한다.

| 수준 | 뜻 | 기본값 |
|---|---|---|
| `listing` | 목록(제목 · 기관 · 등급 · 갱신주기)만 공개, 상세는 자격 필요 | C |
| `detail` | 메타데이터 상세(설명 · 스키마 · 카드)까지 공개, 데이터는 등급대로 | O · S1 · S2 |
| `internal` | 목록조차 기관 내부 한정 (시스템 구조 자체가 민감) | 담당자 수동 |

MCP · 카탈로그 공개 API · AI 시뮬레이션은 이 수준을 먼저 본다. 지금의 `ai_excluded` 와 C 비노출은 이 수준의 특수 사례로 흡수한다 (`ai_excluded` 는 "외부 AI 전송 제외" 로 그대로 두되 공개 수준과 함께 평가).

### 2.5 컬럼 민감 항목 (신규, 등급은 아님)

데이터 사전(STEP 3 ③)에 컬럼마다 두 칸을 둔다. 가이드라인이 컬럼 단위에 요구하는 것은 이것뿐이다.

| 칸 | 값 | 자동 제안 |
|---|---|---|
| 개인정보 유형 | 비개인 / 가명 / 개인 / 민감·고유식별 | 지금의 `_PII_NAME` 탐지 결과를 "개인" 후보로, 주민·여권 패턴은 "민감·고유식별" 후보로 |
| 비식별 처리 | 방법(삭제 · 마스킹 · 범주화 · 가명화 등) · 처리 일시 · 처리 주체 | 없음 (담당자 기록) |

컬럼의 개인정보 유형 최댓값이 2.2 의 "개인정보 유형" 기본값이 된다 (컬럼 → 데이터셋 상향 제안). 이 칸은 뒤에 컬럼 등급을 도입할 때 그대로 토대가 된다.

### 2.6 조합(결합) 등급 (신규)

STEP 2 조합 확정 시 `조합 등급 기본값 = max(구성 데이터셋 등급)`. 가이드라인 3.6.1 "결합 후 재검토" 표에 따라, 공개+제한공유 결합이면 S2 를 제안하고, 제한공유+민감 결합이면 "승인 접근 · 샌드박스 · 반출심사" 안내를 붙인다. 낮추면 사유 필수.

## 3. 기관 등급표 가져오기 (신규 화면)

N²SF 1단계에서 기관이 만든 표를 입력으로 받는다. 형식은 CSV 두 종.

| 파일 | 열 | 매칭 |
|---|---|---|
| 업무정보 목록 | 업무정보명, 소관부서, 정보시스템, 등급(C/S/O), 개인정보 포함, 법령 근거, 비고 | 자산 이름 · 원천 시스템 코드 · 테이블 이름 순으로 유사도 매칭, 담당자가 확인 |
| 정보시스템 목록 | 시스템명, 시스템 코드, 등급, 망 영역 | 자산의 원천 시스템 칸과 매칭 |

가져온 값은 데이터셋의 `기관 분류 등급` 칸(읽기 전용)에 들어가고, 2.2 의 제안과 비교해 세 가지 상태를 만든다.

| 상태 | 조건 | 처리 |
|---|---|---|
| 일치 | 기관표 = 제안 | 제안 확정 버튼 한 번 |
| 기관표가 더 높음 | 예: 기관표 C, 제안 S2 | 기관표를 따른다 (상향은 자동) |
| 기관표가 더 낮음 | 예: 기관표 O, 컬럼에서 개인정보 탐지 | 담당자 확인 필수, 검수 큐 신호 `ORG_GRADE_CONFLICT`, 기관 보안담당 통보용 목록에 포함 |

가져오기 자체가 prov:Activity 로 남고, 파일 해시와 행 수를 기록한다.

## 4. 등급이 바꾸는 동작 (종합)

| 동작 | O | S1 | S2 | C |
|---|---|---|---|---|
| 카탈로그 발행 | 직접 발행 가능 | 검수 큐 (중위험) | 검수 큐 (고위험) | 내부 카탈로그만, 외부 발행 차단 |
| MCP 노출 | 모든 키 | S1 허용 키 | S2 허용 키 + 건별 승인 기록 | 비노출 (존재도 알리지 않음, 지금과 동일) |
| AI 초안 · 시뮬레이션 전송 | 요약 · 통계 | 요약 · 통계 | 통계만 (설명 문장 제외) | 차단 (지금과 동일) |
| 데이터 결합(K 축) | 허용 | 허용 | 검수 큐 고위험 신호 | 결합키 지정 불가 |
| AI 이용조건(표 39) 기본값 | 미정 | AI 학습 조건부, 재배포 불허 | AI 학습 불허, 대량 호출 불허 | 전부 불허 |
| 데이터 카드 | 전부 | 전부 | 전부, 외부 제공본은 샘플 제거 | 외부 제공본 없음 |
| 표 41 차단 | - | - | - | 해당 시 발행 불가 사유 표시 |

## 5. 정본 그래프 · 검증 · 진단 · 검수

### 5.1 정본 표현

```
<dataset> fde:n2sfGrade <def/concept/N2SF-S2> ;
          fde:gradeBasis [ a fde:GradeBasis ;
              fde:personalDataType "pseudonymized" ;     # 비개인·익명·가명·개인·민감
              fde:reidentificationRisk "medium" ;        # low·medium·high
              fde:legalRestriction "trade-secret" ;      # none·trade-secret·statutory·national-security
              fde:suggestedGrade <def/concept/N2SF-S1> ;
              fde:decidedBy "담당자명" ; prov:endedAtTime "..." ;
              rdfs:comment "낮춘/올린 사유" ] ;
          fde:metadataVisibility "detail" ;              # listing·detail·internal
          fde:orgGrade <def/concept/N2SF-C> ;             # 기관 등급표에서 온 값 (있을 때)
          fde:shareProhibited "unique-identifier" .       # 표 41 유형 (해당 시, 반복)
<column>  fde:personalDataType "personal" ;
          fde:deidentification [ fde:method "masking" ; prov:endedAtTime "..." ; fde:by "..." ] .
<combo dataset> fde:combinedGrade <def/concept/N2SF-S2> ; fde:combinedGradeReason "..." .
```

`dcterms:accessRights` 는 지금처럼 F4 축을 따르고, 등급은 `fde:n2sfGrade` 로 유지한다(두 축 분리: 3.6.1 참고표).

### 5.2 SHACL (STEP 6)

- `GradeBasisShape`: S1 이상이면 `fde:gradeBasis` 필수 (Warning), C 이면 `fde:legalRestriction` 또는 개인정보 유형 민감·고유식별 중 하나 필수 (Violation).
- `GradeBelowBasisShape`: `fde:n2sfGrade` 가 `fde:suggestedGrade` 보다 낮은데 `rdfs:comment` 가 없으면 Violation.
- `ShareProhibitedShape`: `fde:shareProhibited` 가 있으면 `dcterms:accessRights` 가 내부 한정(F4-05/08)이어야 함.
- `CombinedGradeShape`: 조합 등급 < 구성 최고 등급이면 사유 필수.
- `ColumnPersonalDataShape`: 컬럼 개인정보 유형이 개인 이상이면 `fde:deidentification` 또는 데이터셋 등급 S2 이상.

### 5.3 STEP 8 진단

- 보안 원칙 항목의 자동 증빙을 "등급 S2 · 근거 3/3 작성 · 표 41 해당 없음 · 메타데이터 공개 수준 detail" 처럼 구조화한다.
- 새 항목 2개(기관 규칙): "등급 판단 근거 작성" (3.6.1), "공유 불가 유형 점검" (표 41). 둘 다 자동 판정.
- 결합 항목에 "조합 등급 재검토 완료" 증빙.

### 5.4 검수 큐 신호 추가

`GRADE_BELOW_BASIS`(고위험), `ORG_GRADE_CONFLICT`(고위험), `SHARE_PROHIBITED`(차단), `COMBINED_GRADE_LOWERED`(중위험), `S2_PUBLISH`(고위험, 기존 "제한공유" 신호 세분화).

| 검수 큐 | 새 신호와 근거 표시, 기관 등급표 충돌은 별도 색 |

## 7. 스튜디오 자체의 N²SF 위치 (운영 문서, `docs/N2SF-CONTROLS.md` 로 별도 작성)

가이드라인 1.0 의 5단계(준비 → 등급분류 → 위협식별 → 보안대책 → 평가·조정)를 스튜디오에 적용한 대응표를 둔다. 핵심 결정만 적으면:

- **분류**: 스튜디오는 **S 영역 정보시스템**. C 데이터의 내용은 다루지 않고 등급 표시와 목록만 가진다(메타데이터 공개 수준 `listing`/`internal`).
- **외부 연결 2곳**: ① Claude API 송신은 O · S1 · S2 데이터셋의 "컬럼명 · 통계 · 담당자가 쓴 설명"에 한정하고 C 와 전송 제외는 차단, 송신 내용은 활동 로그에 남긴다(지금 구현). ② MCP 수신은 키 등급 · 도구 · 일일 상한 · 전 호출 기록(인증 실패 포함).
- **6영역 통제 매핑**: 권한(역할 3종 · 에이전트 키), 인증(JWT · 비밀번호 변경 시 토큰 무효화 · 운영 시 SSO 연동 지점), 분리·격리(프런트/백엔드/DB 컨테이너, 외부 egress 는 Anthropic 엔드포인트만 허용하는 프록시 권고), 통제(검수 큐 HITL · 속도 제한 · 표 41 차단), 데이터(PII 예시값 미저장 · 외부 제공본 샘플 제거 · 저장소 암호화 권고), 정보자산(자산 목록 · 등급 · 보존 5년 · 백업 스크립트).
- **잔여 위험**: 외부 모델 사업자 측 데이터 처리(계약 · 국외 이전 검토는 개인정보 보호법 영역), 컬럼명 자체의 민감성(공개 수준으로 완화), 결합 재식별(검수 큐로 완화).

## 9. 리스크와 결정이 필요한 것

1. **기존 `N2SF-S` 이관을 S2 로 할지 S1 로 할지.** 보수적으로 S2 를 권한다. 기관이 일괄 하향을 원하면 가져오기 화면에서 처리.
2. **표 41 차단을 "차단"으로 할지 "고위험 검수"로 할지.** 가이드라인은 "엄격히 제한"이라 차단을 권하되, 관리자 설정 `FDE_SHARE_PROHIBITED=block|review` 를 둔다.
3. **메타데이터 공개 수준의 기본값.** C → listing 이 맞는지, 기관에 따라 internal 이 기본이어야 하는지. 설정값으로 둔다.
4. **기관 등급표 형식.** 기관마다 다르므로 열 매핑 화면이 필요하다. 1차는 고정 양식 + 샘플 CSV 제공.
5. **N²SF 가이드라인 1.0 원문 확인.** 컬럼·항목 단위 언급과 S 세분화 허용 여부를 기관 보안담당이 NCSC 원문으로 한 번 더 확인해야 한다.
